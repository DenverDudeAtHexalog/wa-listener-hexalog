WhatsApp Listener API

Read every CX group message (text, files, voice notes), get notified the moment one arrives, and, with the admin key, send messages and manage groups.

Getting started

Base URL for this server:

KeyHeaderCan do
Read key API_KEYx-api-key: … or Authorization: Bearer …All GET endpoints for messages, groups, media, stream, webhooks
Admin key ADMIN_API_KEYx-api-key: … (header only, never in a URL)Everything that sends or changes something on WhatsApp
Keys are never shown on this page. Ask the CX tech owner for them and keep them out of front-end code and chat.

Several WhatsApp numbers

The service can run many WhatsApp numbers at once, each as its own isolated login. One read key and one admin key cover all of them. GET /api/numbers lists them with their id, label, phone and state.

Reading: by default you see every number together, and a message received by two numbers (both are in the same group) appears once. Add ?number=2 (id or phone) to see only that number. Message and group objects carry number_id.

Writing: the server picks the number when it is obvious: the only one that is connected, the only one in that group, or the one that received the message you are reacting to or editing. When several could do it, you get HTTP 400 listing them; repeat the request with "number": 2 in the body (id or phone). Responses include "number" so you know which one acted.

curl -X POST "BASE/api/send/text" -H "x-api-key: $ADMIN_API_KEY" -H "content-type: application/json" \
  -d '{"to":"1203630...@g.us","text":"Hello","number":2}'

Limits and the audit log are counted per number. Live events and webhooks include number_id; connection events never include QR codes.

Filters on message lists: limit (max 500), after_uid (newer than a cursor, oldest first, use next_after_uid), before_uid, since, until (ISO times), type (text, image, video, audio, document, sticker, location, contact, poll), sender (phone), search.

Webhooks and live stream

Create a webhook with POST /api/webhooks {"url":"https://you/hook","events":["message.created"]}. The signing secret is shown once. Each delivery carries X-Walistener-Signature: sha256=<HMAC-SHA256 of the raw body>. Failures retry with backoff (10 s up to 1 h, 8 attempts).

Events: message.created, message.updated, message.deleted, reaction, group.updated, connection. The same events stream live from GET /api/stream (Server-Sent Events).

Files and voice notes

No files are stored on the server by default. GET /api/media/:uid fetches the file from WhatsApp at that moment. WhatsApp expires old files, after which the call returns 410; anything you must keep should be fetched when message.created fires. While the number is disconnected the call returns 503.

For transcripts, run speech-to-text on your side when a webhook arrives with is_voice_note: true, then write it back with PUT /api/messages/:uid/transcript.

Safety limits

Automated sending is the quickest way to get a WhatsApp number banned. Every action goes through one queue with random pauses (1.5 to 4 s between messages, 5 to 10 s between group actions). Limits answer 429: 120 messages per hour, 10 new groups per day, 100 member changes per day. Group actions need the linked number to be an admin (otherwise 403). Only message people who expect it. Every write is recorded in GET /api/actions.

Errors are JSON: {"ok":false,"error":"..."} with 400 bad input, 401 bad key, 403 not allowed or not admin, 404 not found, 410 file expired, 429 limit reached, 503 WhatsApp disconnected.
